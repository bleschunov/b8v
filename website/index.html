Datastep Update 4023. Preventing hallucinations when data is missing

This week, Vitaly @vitalykrenel and I came up with a mind-blowing prompt to teach GPT how to understand whether the database actually contains the columns needed to answer a question. We ran into an interesting problem: in most cases, the assistant technically gives a correct answer, but the user subjectively considers it wrong.

Question: What are the most profitable properties in Moscow?
Answer: It looks for properties that generate the most revenue and are managed by departments with “Moscow” in their name. Which is wrong — it should be looking at the property's address. This happens because the table doesn't have a column that explicitly represents the geographical location of the property.

Ideally, we want the assistant to say: “Sorry bro, there’s no address in the table. I’m not a mind reader. Fix the data and we’ll be good, yo.”

The obvious solution is to show GPT the table schema, the user's question, and ask: “Based on this table schema, can you answer the question?” It doesn't work. GPT gets creative and somehow manages to associate “Moscow” with some random column.

So we came up with our mind-blowing solution: chain-of-thought, and that's pretty much the whole story. We ask GPT to go through several steps:

Step 1: Describe what types of data are needed to answer the question.
Step 2: Based on the data schema and the previous answer, identify which types of data are present in the table and which are missing.
Step 3: Based on the previous answers, determine whether it is possible to construct an SQL query that answers the question.

This sequence of steps helps GPT better understand the question and map it to the actual database schema. And as a result, we get exactly what we wanted.

For the first time, I really felt the full potential of GPT. It's not just a language model for answering questions. It's an extremely flexible tool that can be used for all kinds of different purposes and tasks.
